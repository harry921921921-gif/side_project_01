4Service · 訓練與統計
  • WorkoutService — save/update/delete 訓練紀錄；單次最多 50 個動作（REST + MVC 表單共用防線）NEW
  • ·mainLiftProgress() — 主項漸進式加重：手動覆寫接管進度起點，比對「覆寫時間」vs「最近一次真實完成」NEW
  • ·computeDashboardStats() — 本週次數、複合動作訓練量、平均 RPE、最近完成率
  • ·recordAccessoryPr() — 配件動作重量記憶（存進 LiftPr）
5Service · 課表排課引擎（核心賣點）
  • SplitCatalog — 分化表：依一週天數（1~7）決定每天練什麼部位/主項
  • WorkoutPlanService — composeDay/currentQueueComposition — 依週次＋A/B輪替配件、時間預算排課
  • TrainingPlanService — 每人課表偏好、今天/明天排什麼、卡片覆寫（CardOverride）
  • StrengthPrescription — Epley 反推 1RM/%1RM，目標次數區間×RIR 反算次數
  • LiftPrService — saveManual() 手動覆寫重量/組數/次數/休息（含主要動作，非僅配件）NEW
6Service · 帳號與安全
  • CustomUserDetailsService — Spring Security 讀使用者；accountLocked 交給 LoginAttemptService 判斷
  • LoginAttemptService — 連續失敗 5 次鎖 15 分鐘，鎖定 key 改成「信箱＋IP」，避免被拿來鎖別人帳號FIX
  • EmailService — 寄驗證信/重設信；正式環境不再把連結印進 log（SMTP 失敗或未設定都只記錯誤）FIX
  • EmailTokenService — 一次性 token 產生/驗證/標記已用（UUID，單次有效）
  • AiCoachService / SnapshotService / SuggestionService — AI 教練整條鏈已移除（從未接上任何畫面/API 的死碼）刪除
7Service · 動作庫與體重

9DTO（6）· Enum（3）· Repository（9）
DTO：WorkoutRequest/Response、BodyWeightRequest/Response、ExerciseRequest/Response（表單 ↔ Bean Validation ↔ 結構化 ExerciseDto，取代平行 List 參數）
Enum：CompletionStatus（COMPLETE/FAILED/DROPPED/PAIN）、PlanMode（NOVICE/VETERAN）、Role（USER/ADMIN）
Repository：每個 Entity 一個，全部繼承 Spring Data JPA；User/WorkoutSession/BodyWeight/TrainingPlan/LiftPr 系列查詢都帶 User 範圍（findByIdAndUser），沒有裸的 findById 漏洞
